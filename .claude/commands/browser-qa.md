# Browser QA - 전체 UI 테스트

Chrome DevTools MCP를 사용하여 전체 UI QA 테스트를 수행한다.

## 1단계: 환경 확인 및 서버 기동

1. Docker 상태 확인 → 꺼져있으면 Docker Desktop 실행 후 대기
2. `cd infra && docker compose up -d` 로 MySQL, Redis 기동
3. 백엔드: `cd backend && ./gradlew bootRun --args='--spring.profiles.active=local'` (백그라운드)
4. 프론트엔드: `cd frontend && pnpm install && pnpm dev` (백그라운드)
5. 양쪽 health check 통과할 때까지 대기 (backend :8080/actuator/health, frontend :3000)

## 2단계: 테스트 준비

1. `qa-screenshots/` 폴더 생성 (기존 있으면 `roundN/` 서브폴더)
2. 시드 데이터에서 테스트 계정 확인:
   - 관리자: `admin / admin1234`
   - 강사: `instructor1 / admin1234` (박지영), `instructor2 / admin1234` (이수진)
   - 회원: 시드 회원 또는 직접 가입
3. 전체 프론트엔드 라우트 파악 (`frontend/src/app/**/page.tsx`)

## 3단계: 기능 테스트 (Round 1)

### 원칙
- **모든 페이지**를 방문한다
- **모든 버튼, 링크, 폼, 셀렉트박스**를 클릭/입력한다
- **데이터가 있을 때와 없을 때** 모두 확인한다
- **에러 케이스** (잘못된 비밀번호, 빈 폼 제출) 도 테스트한다
- **각 단계마다 스크린샷**을 저장한다
- 파일명 규칙: `{번호}_{페이지명}.png` (예: `01_landing_page.png`)

### 테스트 순서

#### 공통
1. 랜딩 페이지 (`/`) → 역할별 리디렉트 확인
2. 미로그인 시 → `/login` 리디렉트 확인

#### 관리자 시나리오
1. `/admin-login` — 잘못된 비밀번호 → 에러 토스트 확인
2. `/admin-login` — 정상 로그인 → 대시보드 이동
3. `/dashboard` — KPI 카드 4개 데이터 확인, 클릭 반응
4. `/dashboard` — 오늘의 수업 목록, 알림 섹션 (색상 구분)
5. `/dashboard` — 매출 추이 차트 (주간/월간/3개월 탭, 0원 표시)
6. `/members` — 회원 목록 로드, 총 N명 표시
7. `/members` — 검색 (입력 → 필터링 → 비우기 → 복귀)
8. `/members` — 상태 필터 (전체/활성/탈퇴)
9. `/members` — 페이지네이션 (다음/이전)
10. `/members` — 회원 행 클릭 → 상세 모달 (기본정보/정기권/메모 탭)
11. `/members` — 회원 등록 모달
12. `/instructors` — 강사 목록, 검색, 필터, 정렬
13. `/instructors` — 강사 클릭 → 수정 모달
14. `/instructors` — 전화번호 하이픈 포맷 + tel: 링크
15. `/classes` — 시간표 주간 캘린더, 수업 추가 폼
16. `/classes` — 주간 이동 (이전/다음)
17. `/settings` — 설정값 표시, 저장 버튼 (상단+하단)

#### 강사 시나리오
1. `/instructor-login` — instructor1 로그인
2. `/instructor/schedule` — 오늘 탭 (본인 수업만 표시 확인)
3. `/instructor/schedule` — 내일 탭
4. `/instructor/schedule` — 이번 주 탭 (날짜별 헤더, 요약 히트맵)
5. `/instructor/schedule` — 예약 0명 수업 → "예약 없음" 비활성화
6. `/instructor/schedule` — 예약 있는 수업 → "출석 체크" 클릭
7. `/instructor/attendance` — 출석 상태 선택 (출석/지각/결석 범례)
8. 로그아웃 → instructor2 로그인 → 다른 강사 수업만 표시 확인

#### 회원 시나리오
1. `/login` — 회원 로그인 (또는 관리자 토큰으로 회원 페이지 접근)
2. `/home` — 인사말, 요약 카드, 수강권 카드 (이름+D-day+색상), 다음 예약 (날짜순)
3. `/schedule` — 14일 날짜 탭, "오늘" 라벨, 시간 지난 수업 "종료"
4. `/schedule` — 예약 버튼 클릭 → 확인 모달 → 예약 완료
5. `/reservations` — 다가오는 예약 (미래만), 지난 예약 ("완료" 표시)
6. `/reservations` — 취소 버튼 → 스타일 모달 → 취소 처리
7. `/membership` — 수강권 카드 (이름 표시), 상품 목록
8. `/membership` — 상품 클릭 → 모의 결제 모달
9. `/profile` — 출석 이력 + 출석률 %
10. `/profile` — 메뉴: 수강권 구매, 예약 내역, 비밀번호 변경, 알림 설정
11. `/notifications` — 알림 설정 토글 7개, 저장
12. `/signup` — 회원가입 진행 바 (1/3, 2/3, 3/3)
13. `/reset-password` — 비밀번호 재설정 흐름

### 각 페이지 체크리스트
- [ ] 페이지 정상 로드 (무한 로딩 없음)
- [ ] 데이터 정확성 (숫자, 날짜, 이름)
- [ ] 모든 버튼 클릭 반응 (무반응 없음)
- [ ] 폼 입력 + 제출 + 에러 처리
- [ ] 검색/필터 동작 + 초기화
- [ ] 모달 열림/닫힘 (바깥 클릭, X 버튼)
- [ ] 토스트 메시지 (성공/실패)
- [ ] 빈 상태 표시 (데이터 없을 때 안내 문구)
- [ ] 날짜/시간 정렬 정확성
- [ ] 전화번호 하이픈 포맷
- [ ] "준비 중", "미구현", "TODO" 텍스트 없음

### 분류 기준
- **BUG**: 기능이 동작하지 않거나 잘못 동작
- **UX**: 동작하지만 사용자 경험 개선 필요
- **OK**: 정상 동작 확인

### 우선순위
- **P0**: 기능 완전 마비, 보안 이슈, 앱 접근 불가
- **P1**: 주요 기능 오작동, 데이터 오류, 핵심 UX 누락
- **P2**: UX 개선, 사소한 표시 이슈

## 4단계: 수정 및 재검증 (Round 2)

1. P0 → P1 → P2 순서로 수정
2. 프론트엔드 수정 후 `npx tsc --noEmit` 컴파일 체크
3. 백엔드 수정 후 `./gradlew compileJava` 체크
4. 백엔드 변경 시 서버 재시작 (포트 kill → bootRun)
5. 수정된 항목만 브라우저에서 재검증
6. 재검증 스크린샷은 `round2/` 폴더에 저장

## 5단계: 사용자 관점 베타 테스트 (Round 3)

9개 페르소나 관점에서 자연스러움 점검:

### 고객 관점
- **신규가입 회원**: 가입 흐름 직관성, 첫 예약까지 도달 가능한지
- **1주차 회원**: 예약/취소 흐름 자연스러움, 수강권 잔여 인지
- **1개월+ 회원**: 출석 이력, 수강권 갱신, 패턴 파악

### 강사 관점
- **신규 강사**: 스케줄 이해, 출석 체크 방법 인지
- **1주차 강사**: 일일 루틴 효율성, 빠른 출석 마킹
- **1개월+ 강사**: 주간 패턴 파악, 과거 이력

### 관리자 관점
- **첫 사용 관리자**: 시스템 설정, 강사/회원 등록 용이성
- **1주차 관리자**: 대시보드 인사이트, 빠른 액션
- **1개월+ 관리자**: 분석, 트렌드, 효율성, 만족감

### 점검 항목
- 버튼이 클릭 가능해 보이는지 (시각적 어포던스)
- 데이터가 무엇을 의미하는지 즉시 이해되는지
- 색상/크기로 중요도가 구분되는지
- 다음 행동이 자연스럽게 유도되는지
- "이게 뭐지?" 순간이 없는지
- 에러/빈 상태에서 사용자가 무엇을 해야 하는지 안내되는지

## 6단계: 미구현 기능 점검 (Round 4)

전체 코드에서 미구현/플레이스홀더 검색:
```bash
grep -rn "준비 중\|미구현\|TODO\|alert(\|placeholder" frontend/src/app/ --include="*.tsx"
```

발견된 항목은 로컬 시연 가능 수준으로 구현:
- 결제 → 모의 결제 모달 (시뮬레이션)
- 알림 설정 → 토글 페이지
- SMS 인증 → 테스트 엔드포인트 자동 입력
- 기타 → 적절한 에러 메시지 또는 시뮬레이션

## 7단계: 결과 보고

사용자에게 최종 요약 보고:
- BUG/UX/OK 개수
- P0 항목 목록 및 수정 현황
- 수정 파일 목록 (프론트/백엔드)
- 미구현 → 구현 완료 항목
- 남은 권장 사항 (있으면)
