# Browser QA - 전체 UI 테스트

Chrome DevTools MCP를 사용하여 전체 UI QA 테스트를 수행한다.

## 1단계: 환경 확인 및 서버 기동

1. Docker 상태 확인 → 꺼져있으면 Docker Desktop 실행 후 대기
2. `cd infra && docker compose up -d` 로 MySQL, Redis 기동
3. 백엔드: `cd backend && ./gradlew bootRun --args='--spring.profiles.active=local'` (백그라운드)
4. 프론트엔드: `cd frontend && pnpm install && pnpm dev` (백그라운드)
5. 양쪽 health check 통과할 때까지 대기 (backend :8080/actuator/health, frontend :3000)

## 2단계: 테스트 준비

1. `qa-screenshots/` 폴더 생성
2. 시드 데이터에서 테스트 계정(관리자/강사/회원) 확인
3. 전체 프론트엔드 라우트 파악 (`frontend/src/app/**/page.tsx`)

## 3단계: QA 테스트 수행

### 원칙
- **모든 페이지**를 방문한다
- **모든 버튼, 링크, 폼**을 클릭/입력한다
- **각 단계마다 스크린샷**을 `qa-screenshots/` 에 저장한다
- 파일명 규칙: `{번호}_{페이지명}.png` (예: `01_landing_page.png`)
- full page 스크린샷도 필요 시 `_full.png` 접미사로 추가 저장

### 테스트 순서
1. **공통**: 랜딩 페이지 (`/`)
2. **로그인**: 관리자(`/admin-login`), 강사(`/instructor-login`), 회원(`/login`) 로그인 페이지 + 실제 로그인
3. **회원가입/비밀번호 찾기**: `/signup`, `/reset-password`
4. **관리자**: 대시보드 → 회원관리 → 강사관리 → 시간표 → 설정
5. **강사**: 스케줄(오늘/내일/이번주) → 출석체크
6. **회원**: 홈 → 수업예약 → 예약내역 → 프로필 → 수강권

### 각 페이지에서 확인할 것
- 페이지 정상 로드 여부
- 데이터 표시 정확성
- 버튼 클릭 반응
- 폼 입력 + 제출
- 검색/필터 동작
- 모달 열림/닫힘
- 에러 토스트 발생 여부
- 네트워크 에러 여부

### 분류 기준
- **BUG (버그)**: 기능이 동작하지 않거나 잘못 동작
- **IMPROVE (개선)**: 동작은 하지만 UX/UI 개선 필요
- **OK (정상)**: 정상 동작 확인

## 4단계: HTML 리포트 생성

`qa-screenshots/QA_REPORT.html` 생성:

- 한글로 작성
- 스크린샷은 같은 폴더 상대경로로 참조 (base64 인라인 아님)
- 이슈 카드 접기/펼치기 (accordion)
- 이미지 클릭 시 라이트박스 확대
- 구조:
  1. **헤더**: 테스트 일시, 환경, 계정, 범위
  2. **요약 카드**: 버그/개선/정상/전체 개수
  3. **우선순위 바**: P0 즉시 / P1 1주내 / P2 개선
  4. **버그 섹션**: 각 이슈별 카드 + 스크린샷
  5. **개선 섹션**: 각 이슈별 카드 + 스크린샷
  6. **정상 섹션**: 그리드 카드 + 썸네일

### 우선순위 기준
- **P0**: 기능 완전 마비, 보안 이슈, 앱 접근 불가
- **P1**: 주요 기능 오작동, 데이터 오류, 핵심 UX 누락
- **P2**: UX 개선, 사소한 표시 이슈

## 5단계: 결과 보고

최종 요약을 사용자에게 보고:
- 버그/개선/정상 개수
- P0 항목 목록
- 핵심 구조적 문제 (있으면)
- 리포트 파일 경로
